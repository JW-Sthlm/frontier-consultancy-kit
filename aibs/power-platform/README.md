# AIBS / HVE Squad for Power Platform feature and schema decisions

**Ten client decision exercises for the Power Platform lane.**

Open the [orientation](exercise/START-HERE.md), [course index](exercise/README.md), [landing](index.html) or [teaching deck](presentation/index.html).

## Purpose

Learn to use HVE Squad to decide which technology-specific features are needed and what logical data model supports them.

The core follows client evidence -> feature choices -> schema alternatives -> change impact -> a first-release decision pack. It does not focus on formulas, code debugging, action-card configuration or an already prescribed database blueprint.

## Technology remains specific

Canvas offline/media/checklist features, model-driven casework/stages, flow routing/follow-up, agent knowledge/actions, portal self-service/access, custom workbench interaction and BI grain/lineage all shape the decisions.

Learners compare capability value and limitations, then justify entities, fields, requiredness, cardinalities, lifecycle, ownership and access. More features/tables are not automatically better.

- [Output navigation](exercise/OUTPUTS.md), [receipt](exercise/client/offerings/lab-receipt.md) and [offering canvas](exercise/client/offerings/offering-canvas.md).

The Cowork contract is unchanged: new work enters through `squad_run`, the server coordinates and actual artifacts/provenance matter. No manual specialist dispatch or invented execution.

## Core versus implementation

Core completion is a source-backed feature/schema decision pack and a receiving person's explanation/next question. Live HVE needs the actual connected/rehearsed project; a desk walkthrough is separate.

No provisioned Power Platform app is required. Earlier [maker material](exercise/guided-builds/README.md) is optional downstream reference, not the learning objective or a fixed schema answer. Any actual implementation needs separately authorized preparation and evidence.

## Using the material

Use the browser readers under `workshop/` or download the linked Markdown source. The copied prompt and browser button carry the same complete payload.

Real learner choices, accepted outputs, and environment or run observations cannot be baked into a static prompt. Requests must retrieve the actual project evidence or ask for missing inputs before dependent work; they must not fabricate earlier selections.

This published material is a learning aid. Live rehearsal, representative learner timing, platform entitlement checks, and authorized implementation remain separate gates.
